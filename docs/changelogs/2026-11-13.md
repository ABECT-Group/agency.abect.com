## Запит 2 — Деплой за патерном QRHUB (abect): гілка `prod`, спільна MongoDB, `secrets/`

**Гілка:** `chore/deploy-like-abect`
**Запит власника:** проаналізувати, що на VPS, і привести agency.abect.com до того ж патерну, що й QRHUB (`~/www/abect`): спільна база, `secrets/`, реліз з гілки `prod` вручну через restart-скрипт. Автоматичний CI/CD — не потрібен.

### Що виявилось на VPS (вивід власника + `QRHUB/vps/README.md`, `DEPLOY.md`)
- Тека проекту — **`~/www/agency-abect`**, а `~/www/abect` — QRHUB. Документація й `../scripts/restart.sh` вказували на `/home/admin/www/abect`: запуск такого скрипта на сервері стягнув би `main` у робочу копію QRHUB (вона на `prod`) і перевикотив би чужий прод.
- Окремого контейнера `abect-mongo` давно немає: БД `agency-abect` живе в **спільному** контейнері `mongodb` (replica set `rs0`, `/opt/mongodb`), доступ через мережу `mongodb-net`. ISS-005 (2026-11-09) помилково прибрав `mongodb-net` з compose — реліз `main` у такому вигляді втратив би базу.
- Образ `frontend-app` (тег з назви теки, без `name:`/`image:`), порт `0.0.0.0:3333`, стара версія `88deb2a`, `frontend/media` належить root.
- Базу agency вже щоночі знімає спільний `/opt/mongodb/backup-mongo.sh`; `media/` не бекапить ніхто.

### Зроблено
- `docker-compose.yml`: `name: agency-abect`, `image: agency-abect-frontend:latest`, `env_file: ../secrets/.env.frontend`, мережа `mongodb-net` (повернуто), без `abect-shared`, порт `127.0.0.1:3333`.
- `vercel.json`: `prod` теж не деплоїться на Vercel.
- `../scripts/` (поза git): `restart.sh` → **`restart-frontend.sh`** (шляхи `~/www/agency-abect`, гілка `prod`, запобіжник на «чужий» репозиторій, перемикання `main` → `prod` при першому запуску, `chown media` через образ без sudo, прибирання контейнера старого compose-проекту, `exit 1`, якщо не healthy); `backup.sh` → **`backup-media.sh`** (лише `media/`, cron під admin без sudo); `README.md` переписано. `../mongodb/README.md` — позначено застарілим.
- `docs/deployment.md` переписано: структура, `secrets/.env.frontend`, регулярний реліз `main → prod`, відкат, **покроковий одноразовий перехід** з поточного стану сервера (страхувальні копії без sudo, секрети, скрипти, реліз, перевірка, повернення старої версії, прибирання). Оновлено `README.md`, `CLAUDE.md`, `git-workflow.md` (реліз через `prod`), `architecture.md`, issues (виправлено опис ISS-005/006/008, ISS-027).
