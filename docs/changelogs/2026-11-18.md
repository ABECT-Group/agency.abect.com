## Запит 13 — Перевірка адаптиву всіх сторінок (iPhone SE і далі)

**Гілка:** `feature/redesign-fixes`
**Запит розробника:** ще раз ретельно перевірити адаптив на всіх сторінках (iPhone SE тощо), щоб нічого не ламалось і не вилазило.

### Як перевіряли
- 45 сторінок (UA і EN, усі послуги, кейси, категорії й статті з локальної БД) — автоматично на 320 / 375 / 414 / 768 / 1024 px (UA) і 320 / 375 px (EN): горизонтальна прокрутка й елементи за краєм екрана; на телефонах — ще відкриті меню, модалка заявки, віджет калькулятора, селект. Плюс: H1 / бейджі ширші за свій блок, тире на початку рядка H1, вміст ширший за свій блок; скриншоти 12 шаблонів на 320 px переглянуто вручну.

### Виправлено
- `/privacy-policy` 320px — H1 «конфіденційності» ширший за екран (горизонтальна прокрутка) → розмір від ширини екрана (`PrivacyPolicy.scss`).
- H1 усіх внутрішніх сторінок (`PageHero`) — довгі слова капсом («НАЛАШТУВАННЯ», «БАГАТОСТОРІНКОВИЙ») обрізались на 320px → на ≤ 480px `clamp(21px, 7.4vw, 30px)` + перенос як запасний варіант; тире з назв CMS («VELOX RIDE — продаж…») більше не стає на початок рядка (нерозривний пробіл у `PageHero.tsx`; NBSP у `messages` для «Про нас» прибрано).
- Головна, «Обговорити проєкт» ≤ 480px — 3D-об'єкт закривав заголовок і текст → менший і вище (`DiscussProject.scss`).
- Картки цін ≤ 400px — назва одним словом («Багатосторінковий») залазила під декор → менший декор і шрифт назви (`PlanCard.scss`).
- Картки статей / проєктів — довга категорія вилазила з пігулки фіксованої висоти → `min-height` (`PortfolioCard.scss`).
- «Контакти» 320px — картки пошти / телефону виходили за блок (`minmax(240px)` → `minmax(min(240px, 100%))`), номер Viber і час роботи розривались → без розриву, менший шрифт на ≤ 360px (`ContactsPage.scss`).
- Віджет калькулятора — на телефоні піднімається над банером cookie, поки той на екрані (підказка ховалась під банер) (`CalculatorWidget.tsx`, `.scss`).

### Перевірено
- Після виправлень: заголовки й бейджі — 0 проблем на 320 / 375 (UA, EN); вміст за межами блоку на `/contacts` 320 — 0; `npm run typecheck`, `npm run lint` — без помилок.

### Не робилось / наступні кроки
- **Повний повторний прогін усіх сторінок і ширин після останніх правок не встиг** (ліміт сесії) — зробити наступним кроком.
- `/calculator` на 375px: вміст кроку на 16px ширший за свій блок — не розібрано (сторінка калькулятора — етап 6 редизайну, ISS-043).
- Хлібні крихти статей із довгою категорією — ширші за рядок (обрізаються, як задумано?) — переглянути.
- Навмисні виступи (не дефекти): обкладинка в картці тексту (від'ємні відступи), скляне коло кнопок-стрілок, стрілки слайдера, повернуті картки «Етапів».

## Запит 12 — Віджет калькулятора (як чат підтримки)

**Гілка:** `feature/redesign-fixes`
**Запит розробника:** кнопка-віджет у стилі сайту; клік відкриває праворуч панель із калькулятором (не посилання на сторінку). На головній кнопка з'являється після першого екрана, на інших сторінках — одразу, на `/calculator` — немає. Спершу кнопка, через 10 с — текст «Вітаю, давай прорахуємо вартість сайту» з хрестиком у колі в лівому верхньому куті.

### Зроблено
- `components/CalculatorWidget/`: кругла кнопка праворуч унизу (градієнт CTA, світіння, м'яка пульсація кільця), поява з анімацією; підказка — скляна «бульбашка» над кнопкою, хрестик у колі в лівому верхньому куті, клік по тексту відкриває калькулятор; закриту підказку не показуємо до кінця сесії (`sessionStorage`). Панель — скляне вікно 440×680 над кнопкою з шапкою «Калькулятор вартості сайту» й хрестиком; на телефоні — на весь екран. Esc закриває, фокус переходить у панель і повертається на кнопку; `role="dialog"`, `aria-expanded` / `aria-controls`. Перехід на іншу сторінку (зокрема `/thx` після заявки) закриває панель. Видимість: головна — після прокрутки 60 % висоти екрана, інші — одразу, `/calculator` — без віджета.
- Калькулятор у панелі — той самий компонент у компактному режимі (`compact`: без H1 сторінки й контейнера, 2 колонки типів проєкту) (`components/Calculator/Calculator.tsx`, `.scss`); код калькулятора вантажиться лише при першому відкритті (`next/dynamic`, `WidgetCalculator.tsx`); вибір лишається між відкриттями (і спільний зі сторінкою — localStorage калькулятора).
- Конфіг калькулятора — у layout (`[locale]/layout.tsx`) з CMS із фолбеком на дефолти; перетворення конфігу винесено з `calculator/page.tsx` у спільну `toCalculatorConfig()` (`src/client/lib/calculator.ts`). Тексти — `Common.CalculatorWidget` (UA / EN).
- Попутно: у `Select` (запит 6) закритий список займав місце під полем — глобальний `.glass` перебивав `position: absolute`; виправлено вищою специфічністю (так само в панелі віджета).

### Перевірено
- `npm run typecheck`, `npm run lint` — без помилок.
- Вручну (dev, headless Chrome): головна — на першому екрані кнопки немає, після прокрутки є; `/portfolio` — одразу; `/calculator` — віджета немає; через 10 с — підказка над кнопкою; хрестик ховає її (і запам'ятовує); клік — панель 440×680 (телефон 390 px — на весь екран), у ній крок 1 → вибір → крок 2; форма «Обговорити проєкт» — відступ після селекта знову 16px.

### Не робилось / наступні кроки
- На телефоні банер cookie (на всю ширину знизу) перекриває кнопку, доки його не закриють — свідомо: банер важливіший.
- Повний сценарій заявки з віджета (до `/thx`) не проганявся — це та сама форма калькулятора, що на сторінці.
